## C1 — Risk-mitigation moves: suggest-only vs automatic (contradiction, resolved)

> only suggest

Resolution (source of truth): the system only **suggests / proposes** risk-mitigation
resource moves; a human decides and executes them. The process-level "risk management
policy → resource automatically added" auto-substitution does **not** hold — override it
to suggest-only.

## C2 — Worker lacking skills vs permit (contradiction, resolved)

> hard block for permit

Resolution (source of truth): a missing **permit / authorization** is a **hard block**
(cannot assign). A missing **skill / qualification** is an **accepted risk** (assignment
allowed). This settles the conflict in favour of the L65–69 reading; the broader L20–22
wording ("kwalifikacji czy zezwoleń") is reconciled as: hard block on permits only, skills
are soft.

## C3 — Ordering: resource check gates stage planning vs stages first (contradiction, resolved)

> no upfront check

Resolution (source of truth): there is **no upfront resource-availability check** gating
whether stage planning starts. Stages are defined and parallelized first; resource
availability is checked later, at allocation (the process-level automatic-mode ordering).
The big-picture "czy w ogóle są zasoby? … jeszcze nie warto planować etapów" is not a hard
gate on planning.

## Q4 — Regulatory / permits (strategic gap, answered — turn 2)

Interpretation: **any** required permit that is missing is a **hard block** on assignment
(not a specific named regime — all permits treated as hard blocks). Consistent with C2:
permit missing = hard block; skill missing = accepted risk.
